# 데드락

> 작성일: 2026-11-19

## 한 줄 요약

두 트랜잭션이 **서로가 가진 락을 기다리면서** 둘 다 영원히 진행하지 못하는 상태다. DB는 한쪽을 강제로 롤백(희생자)해서 풀어준다.

## 내용

### 발생 조건 4가지 (모두 만족해야 발생)

| 조건 | 의미 |
| --- | --- |
| 상호 배제 | 자원을 한 번에 하나만 쓸 수 있음 |
| 점유 대기 | 자원을 가진 채로 다른 자원을 기다림 |
| 비선점 | 다른 쪽이 가진 자원을 강제로 뺏을 수 없음 |
| 순환 대기 | A는 B를, B는 A를 기다리는 원형 구조 |

### DB에서 흔한 예

```
트랜잭션 A: 상품 1 재고 UPDATE (락 획득) → 상품 2 재고 UPDATE (대기)
트랜잭션 B: 상품 2 재고 UPDATE (락 획득) → 상품 1 재고 UPDATE (대기)
```

- 장바구니에 담긴 순서대로 재고를 차감하면 요청마다 잠그는 순서가 달라서 발생한다.

### 예방

1. **락 순서 통일**: 상품 ID 오름차순처럼 항상 같은 순서로 잠근다. (순환 대기 제거)
2. **트랜잭션을 짧게**: 트랜잭션 안에서 외부 API 호출 등 오래 걸리는 작업을 하지 않는다.
3. **인덱스 확인**: 조건 컬럼에 인덱스가 없으면 필요 이상으로 많은 행·범위를 잠근다.
4. **조건부 UPDATE**: 조회 후 수정 대신 한 쿼리로 처리해 락 보유 시간을 줄인다.

### 발생했을 때

- DB가 희생자 트랜잭션을 롤백하고 에러를 던진다(SQL Server 1205, MySQL 1213).
- 애플리케이션에서 이 에러는 **재시도** 대상으로 처리한다.

## 헷갈렸던 점 / 주의할 점

- 4가지 조건 중 "상호 배제"와 "상호 대기"를 헷갈렸다. 조건 이름은 **상호 배제**이고, 서로 기다리는 원형 구조는 **순환 대기**다.
- 데드락은 "느린 것"이 아니라 "영원히 안 끝나는 것"이다. 락 대기 타임아웃과 구분한다.
